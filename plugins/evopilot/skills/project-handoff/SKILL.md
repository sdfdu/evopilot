# Project Handoff

1. Verify the current state against accessible files, issue status, version control, or recent validation. Use the intended recipient's context and access to determine which details belong in the handoff.
2. State the objective, completed work, work in progress, known issues, and the immediate next action. Identify key files, branches or revisions, and relevant project decisions when applicable.
3. Supply reproducible setup or verification steps relevant to resuming work. Label checks as passed, failed, or unrun. Point to the location of any local changes or unpublished work.
4. Return the handoff in chat or update the existing project handoff document if requested. Avoid exposing secrets or unrelated private context, and obtain authorization before sending it externally.
